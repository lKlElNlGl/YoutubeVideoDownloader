# YoutubeVideoDownloader — Android

Android-версия [medneem/YoutubeVideoDownloader](https://github.com/medneem/YoutubeVideoDownloader), лицензия MIT. Оригинальная иконка сохранена в `assets/app.svg`.

## Скачать программу

[**Последняя версия APK в GitHub Releases**](https://github.com/lKlElNlGl/YoutubeVideoDownloader/releases/latest) — APK размещается непосредственно в релизе, без ZIP.

Минимум **Android 10 (API 29)**. Релизы подписаны одним постоянным сертификатом через GitHub Actions Secrets и устанавливаются поверх предыдущих релизов. Самый первый тестовый APK 0.1.0 был подписан временным ключом и требует однократного удаления перед установкой релизной версии.

## Возможности

- Скачивание одного видео по ссылке YouTube; MP4, до 4K, или MP3 192 кбит/с через FFmpeg.
- Информация **до скачивания**: название, миниатюра, длительность, список доступных разрешений. Нажмите «Информация о видео».
- **Очередь загрузок**: добавляйте несколько ссылок, они скачиваются последовательно. Очередь и состояние заданий сохраняются, отменённые или ошибочные задания можно повторить, завершённые очистить.
- **Фоновая загрузка**: foreground service с уведомлением, прогрессом, кнопкой отмены и удержанием CPU awake во время скачивания. Можно свернуть приложение или выключить экран; не смахивайте уведомление загрузки и не выполняйте принудительную остановку приложения.
- **Выбор папки сохранения**: через системный Android Storage Access Framework. По умолчанию `Downloads/YoutubeVideoDownloader` (MediaStore), пользовательская папка — через сохранённое разрешение доступа. Указанная папка записывается в каждое задание отдельно; изменение настройки не перенаправляет уже добавленные задачи.
- В меню настроек: HTTP(S)-прокси, импорт `cookies.txt` Netscape, кнопка обновления **yt-dlp независимо от APK**, проверка обновлений приложения.
- Программа при запуске проверяет GitHub Releases. Скачиваемый APK проверяется по SHA-256 и сертификату приложения перед предложением установить обновление.
- Имя сохранённого файла — оригинальный заголовок YouTube с правильным расширением, включая кириллицу (длинные заголовки ограничиваются в байтах).

## Использование

1. Вставьте HTTPS-ссылку YouTube. По желанию нажмите «Информация о видео».
2. Выберите «Видео MP4» или «Аудио MP3» и максимальное качество.
3. Нажмите «Добавить в очередь загрузок».
4. Продолжайте пользоваться устройством; статус и уведомление останутся доступны даже после сворачивания экрана.
5. В раскрывающихся «Настройках» можно выбрать папку, импортировать cookies, настроить прокси, открыть каталог и отдельно обновить yt-dlp.

Если cookies включены, но файл не выбран, задание не добавляется. Не публикуйте `cookies.txt`: это чувствительные сессионные данные. Файл хранится в приватном каталоге приложения.

## Ограничения

- Очередь последовательная; одновременные загрузки и плейлисты пока не реализованы. Количество активных задач ограничено 50.
- Фоновая работа зависит от режима энергосбережения Android. Принудительная остановка приложения прекращает работу, но несохранённые задания повторно ставятся в очередь при следующем запуске. На Android 15+ система может ограничивать длительность службы `dataSync`; работа не гарантируется бесконечно долго.
- Выбранная папка должна оставаться доступной для записи. Некоторые файловые менеджеры Android не открывают папку напрямую; используется системный диалог открытия файлов.
- Для больших видео необходимо свободное место **во внутреннем кеше** приложения до переноса в папку назначения, плюс место на целевом накопителе. Временные файлы удаляются после загрузки, ошибки или отмены.
- Набор разрешений зависит от доступности исходных форматов; не любой ролик поддерживает 4K.
- `yt-dlp` может перестать работать после изменений со стороны YouTube, даже если APK устанавливается и собирается. Для этого есть отдельная кнопка обновления движка.
- Публикационный CI проверяет сборку, тесты и подпись, но реальные загрузки, Android Storage Access Framework и поведение разных производителей смартфонов требуют проверки на устройстве.

## Сборка, тестирование, публикация

GitHub Actions workflow `Android CI` запускает `testDebugUnitTest assembleDebug`. Workflow `Publish signed Android APK` на push в `main` выполняет тесты, создаёт подписанный APK и напрямую публикует APK с SHA256SUMS в Releases.

Для релиза необходимы GitHub Secrets `ANDROID_SIGNING_KEY_PEM` (постоянный приватный ключ) и `ANDROID_SIGNING_CERT_PEM` (соответствующий X.509 сертификат). Никогда не добавляйте приватный ключ в Git. После публикации проверьте релиз и установите APK на телефон.

Зависимости: [youtubedl-android](https://github.com/yausername/youtubedl-android) 0.18.1, yt-dlp, FFmpeg и QuickJS; соблюдайте условия лицензирования сторонних библиотек. Скачивайте материалы только при наличии необходимых прав.


## Следующая версия 0.3.0

Новый внешний вид «Тёмный премиум» (красные кнопки, графитовые карточки, новое оформление иконки), три режима темы — Светлая / Тёмная / Как в системе. Добавлено распознавание ссылок с параметром `list`, просмотр списка роликов, выбор всех или отдельных видео и добавление выбранных роликов в сохранённую очередь. Прогресс плейлистов группируется в очереди; недоступные видео пропускаются при получении списка.

Механизм обновлений согласован с SSH Button Next: проверка при запуске и каждый час в фоне (WorkManager), уведомление со звуком при появлении новой версии, видимый размер APK, прогресс, этапы SHA-256 и проверки подписи, системная установка. Во время скачивания нажатие за пределами диалога и системная кнопка «Назад» не отменяют загрузку; отмена только по явной кнопке. Диалог сохраняет высоту при смене этапов. Уведомления могут быть отключены пользователем в настройках Android.

Версии задаются вручную в `app/build.gradle` (`versionName`, `versionCode`). CI запускается на ветках main и feature/**. Публикация APK выполняется через отдельный коммит, меняющий `.github/RELEASE_TRIGGER.txt`, либо ручной запуск workflow. Одна сборка не создаёт несколько релизов, и неудачные сборки не влияют на номер версии.

Плейлисты загружаются по одному элементу; общая очередь рассчитана на 2000 активных заданий. Для больших списков потребуется свободное место в хранилище. Поведение экрана, фоновых служб, предпросмотра и Google/YouTube необходимо проверять на реальном устройстве.
